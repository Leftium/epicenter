Row editor callers

One folder.tables.todos.edit(stem) editor for a todo row, shared by a vanilla DOM view, a Solid view, and a Svelte 5 view. The editor's draft is the row's fields and body; a save writes the whole row in canonical form.

This is a real, persisted folder opened with the production browser opener, in this browser's default storage: opening…

Loading writes nothing to a folder that already has todo rows, and opening a row never rewrites it. Faults a browser folder does not produce on demand, such as a held or lost save reply, are covered by unit tests with fake storage (src/editor.test.ts), not by this page.

Journeys to try
  1. Type A as the title in any view. All three show it and its issue; Save refuses and writes nothing. Type on to ABC and Save.
  2. Reload this tab. The saved row reopens from the folder. An unsaved draft lives only in the page and is gone.
  3. Open this same address in a second tab. Save in one tab: a clean editor in the other follows. Type in the other first, then save here: it keeps its draft and offers "Take this version" or "Keep mine: save".
  4. With plan clean, press "Same values, reformatted": the editor follows and stays clean. Save rewrites it canonically and keeps owner and labels.
  5. Unmount the three views, change the file, mount them again: they show the same retained editor and its latest read.
  6. Choose tagged or urgent: opening refuses and shows the exact text. Fix it and overwrite; the row opens. gone starts from a new row.
  7. "Remove file" keeps the draft and baseline; "Save my draft" writes it back.
