Row editor callers

One folder.tables.todos.edit(stem) editor for a todo row, shared by a vanilla DOM view, a Solid view, and a Svelte 5 view. Each input is the complete row, accepted at once and saved in order: one write runs, and only the latest input waits behind it. There is no Save button.

This is a real, persisted folder opened with the production browser opener, in this browser's default storage: opening…

Loading writes nothing to a folder that already has todo rows, and opening a row never writes. Faults a browser folder does not produce on demand, such as a held or lost save reply, or a removal between an input and its write, are covered by unit tests with fake storage (src/editor.test.ts) and by the OPFS acceptance page, not by this page.

Journeys to try
  1. Edit the title of plan in any view. The other views follow, and the status panel shows the canonical text each keystroke saved: the comment is gone, owner and labels stay.
  2. Select the whole title and type A. A one-letter title can be written, so it is saved as typed. The row is now invalid, and every view shows its Markdown source with the issue. Fix the title there; the row is valid again, and that view keeps the source until "Edit fields".
  3. Choose "(none: remove the field)" for the priority. The key is omitted, so the saved row has no priority and is invalid until it is repaired the same way.
  4. Choose tagged or urgent. Each opens as an invalid row; repair it in the source view of the same editor. In crlf, a body edit keeps the body's CRLF and writes the header in LF; a source edit writes CRLF on every line. If the row is missing, Reset writes it.
  5. Choose gone. Opening returns NotFound and no editor; nothing creates the file. "Write the seed text" under "Another caller" creates it on purpose; then try opening again.
  6. With a row open, "Remove the file" under "Another caller". The views keep the row; typing fails with NotFound, and saving never recreates the file. "Write the seed text" brings a file back, and "Read the file again" shows it.
  7. Unmount the views: nothing subscribes to the row, and the editor stays. Change the file as another caller, then mount them again: they show the editor's snapshot until "Read the file again".
  8. Open this address in a second tab. Typing in one tab shows in the other after "Read the file again".
  9. Close, Open, another row, and Reset run one at a time, to the end. Each first stops input, then waits for the running save. After a failed save it asks: keep editing, or discard that input.
